## 1. できること

- 画面はA案のまま。上に日報、下にスクロールすると日計表が出る。
- 依頼書（2026.10.9）の内容を反映した。
  - 確認欄はココナ・経理・管理部の3つで、クリックすると「済／未」を選べる（日報・日計表それぞれ）。
  - 弁当類残数は5行（おにぎりセットの下に2行の空き行）。
  - おまかせ・PETなどの表に「項目・数量・備考」の見出しを付け、備考欄を広くした。
- 上のバーで日付を選ぶ（‹ › と「今日」でも移動）と、その日の内容を読み込む。未登録の日は空の様式で、弁当の品名だけ直近の登録日から引き継ぐ。
- 保存は「保存する」ボタンか Ctrl+S。入力が止まって5秒たつと自動でも保存する。日付を移る前にも保存する。
- 「印刷」で日報と日計表を1枚ずつ印刷できる。
- 売上計・掛売計・現金在高・過不足・在高計・Cocona分・内Café売上・弁当の販売数は自動で計算する。過不足と在高計は、金種を1つでも入力するまでは空欄。

## 2. スプレッドシートの中身

| シート | 内容 |
|---|---|
| 日報日計表 | 1日1行。日付・更新日時・更新者、入力値、自動計算値、確認欄（済）。日付順に並ぶ |
| 設定 | B2 が釣り銭（初期値 120,000）。変えると過不足・在高計の計算に反映される |

どちらのシートも、アプリを初めて開いたときに自動で作られる。シートのタイムゾーンも日本時間に合わせる。

計算式のうち「過不足」「在高計」「医局(現金)を掛売に含めるか」は確認待ちのため、画面とシートの見出しに「仮」と付けている。

## 3. 本番の作り方（会社ドメインのアカウントで行う）

1. 会社ドメインのアカウントで Google ドライブを開き、新しいスプレッドシートを作る。名前は「Cocona 日報・日計表」。
2. そのスプレッドシートで「拡張機能 → Apps Script」を開く。
3. エディタに次の3つを用意し、GitHub の `gas/` から中身を貼り付ける。
   - `コード.gs`（GitHub では `コード.js`）
   - `index.html`（「＋ → HTML」で作り、名前は `index`）
   - `appsscript.json`（「プロジェクトの設定 → 『appsscript.json』マニフェスト ファイルをエディタで表示する」にチェックすると出る）
4. `appsscript.json` の `webapp.access` を `"MYSELF"` から `"DOMAIN"` に変えて保存する（会社ドメインのアカウントなら誰でも開けるようにするため）。
5. `コード.gs` 先頭の `SPREADSHEET_ID` を、1. で作ったスプレッドシートのIDに書き換える（コンテナバインドなので通常は使われないが、念のため）。
6. 「デプロイ → 新しいデプロイ → 種類：ウェブアプリ」。実行ユーザーは「自分」、アクセスできるユーザーは「（ドメイン名）内の全員」にしてデプロイする。
7. 初回は権限の承認画面が出るので承認する。求める権限は「このスプレッドシートの読み書き」と「メールアドレスの取得（更新者の記録用）」の2つだけ。
8. 表示されたウェブアプリのURLを、事務所のPCのブックマークに登録する。

### 本番を更新するとき

GitHub の `gas/` の内容をエディタに貼り直し、「デプロイ → デプロイを管理 → 編集 → バージョン：新バージョン → デプロイ」。URLは変わらない。

- 保存・読み込みをメモリ上で再現した環境で、サーバー側15項目（計算、同じ日の上書き、日付順の並び、弁当名の引き継ぎ、不正な日付の拒否など）と、画面側17項目（日付と和暦の表示、確認欄、自動計算、保存、日付移動前の自動保存、値の復元）がすべて通った。
- 開発版の Web アプリで、表示と保存ができ、スプレッドシートに1行記録されることを確認した（2026-10-24 の空の行）。
